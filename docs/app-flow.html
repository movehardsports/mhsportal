1. Przegląd systemu i architektura

MHS (MoveHard Sports) to platforma łącząca marki sportowe z atletami. Marki publikują kampanie, atleci (w przyszłości) mogą aplikować. Aplikacja zbudowana jest w Next.js 16 z App Routerem po stronie serwera, autoryzacja i baza danych oparte są na Supabase.

Stack technologiczny

Frontend

  • Next.js 16 App Router
  • React Server Components
  • Tailwind CSS
  • Headless UI
  • Heroicons

Backend

  • Next.js Server Actions
  • Supabase (Auth + DB)
  • Zod (walidacja)
  • DAL (Data Access Layer)
  • React cache()

Auth

  • Supabase Auth
  • Cookie-based sessions
  • SSR middleware
  • Server-only DAL
  • RLS w Supabase

Typy kont

Atleta athlete

  • Imię i nazwisko (first_name, last_name)
  • Dyscypliny sportowe
  • W przyszłości: aplikowanie na kampanie

Marka brand

  • Nazwa marki (brand_name)
  • Dyscypliny zainteresowań
  • CRUD kampanii marketingowych

2. Modele danych

Profile (discriminated union)

Profil użytkownika jest przechowywany w tabeli profiles w Supabase. TypeScript używa discriminated union na polu account_type.

type BaseProfile = {
  id: string
  account_type: 'athlete' | 'brand'
  onboarding_completed: boolean
  created_at: string
  updated_at: string
  disciplines: Discipline[] | null
}

type AthleteProfile = BaseProfile & {
  account_type: 'athlete'
  first_name: string
  last_name: string
  brand_name: null
}

type BrandProfile = BaseProfile & {
  account_type: 'brand'
  brand_name: string
  first_name: null
  last_name: null
}

type Profile = AthleteProfile | BrandProfile

Campaign

type CampaignStatus = 'draft' | 'active' | 'closed' | 'archived'

type Campaign = {
  id: string
  brand_id: string   // FK → profiles.id
  title: string      // max 200 znaków
  description: string // max 5000 znaków
  status: CampaignStatus
  disciplines: Discipline[] | null
  created_at: string
  updated_at: string
}

Discipline

const DISCIPLINE_IDS = ['crossfit', 'triathlon', 'motorsports'] as const

type Discipline = 'crossfit' | 'triathlon' | 'motorsports'

7. Flow: Kampanie — CRUD

Lista kampanii /dashboard/campaigns

getCampaigns() — DAL (brand_id = user.id)
↓
Brak kampanii → CTA: „Create your first campaign"
Lista kart kampanii z: tytułem, opisem (clamp), statusem, linkiem Preview
↓ klik „Preview"
/dashboard/campaigns/:id

Tworzenie kampanii /dashboard/campaigns/new

  1. 1
    Klik „New Campaign" na liście. Strona renderuje CampaignForm bez danych wstępnych
  2. 2
    Pola: Title (max 200), Description (textarea, max 5000), DisciplinePicker (min 1)
  3. 3
    Server Action createCampaign: walidacja Zod → sprawdzenie profilu brand → campaigns.insert()
  4. 4
    Sukces: redirect na /dashboard/campaigns

Szczegóły kampanii /dashboard/campaigns/:id

Server Component. Pobiera kampanię przez getCampaign(id) (filtr: brand_id = user.id). Jeśli nie znaleziono — notFound().

Wyświetla:
  • Tytuł + status (badge)
  • Opis (whitespace-pre-wrap)
  • Dyscypliny jako pill-badges z labelami z DISCIPLINES
  • Daty: Created, Last updated
  • Przyciski akcji: Edit (link) + Delete (form + confirm dialog)

Edycja kampanii /dashboard/campaigns/:id/edit

  1. 1
    Server Component pobiera kampanię i przekazuje ją jako prop do CampaignForm
  2. 2
    Formularz prefilluje pola przez defaultValue={campaign?.title} itd.
  3. 3
    Server Action updateCampaign(id) (partial application przez .bind(null, id)): walidacja → campaigns.update() z filtrem eq('brand_id', profile.id)
  4. 4
    Sukces: redirect na /dashboard/campaigns

Usuwanie kampanii

  1. 1
    DeleteButton renderuje <form> z ukrytym polem id
  2. 2
    Click handler pokazuje window.confirm() — jeśli użytkownik anuluje, e.preventDefault()
  3. 3
    Server Action deleteCampaign: weryfikacja profilu brand → campaigns.delete() z filtrem brand_id
  4. 4
    Redirect na /dashboard/campaigns

Bezpieczeństwo danych kampanii (RLS)

Wszystkie zapytania do tabeli campaigns zawierają filtr .eq('brand_id', user.id) — użytkownik może odczytać i zmodyfikować wyłącznie swoje kampanie. RLS w Supabase stanowi drugi poziom ochrony.

Tabela guardów

MiejsceWarunekAkcja

onboarding/page.tsx profile.onboarding_completed redirect /dashboard
onboarding/page.tsx account_type ≠ 'athlete' && ≠ 'brand' redirect /login
dashboard/layout.tsx !profile redirect /login
dashboard/layout.tsx !profile.onboarding_completed redirect /onboarding
dashboard/(brand)/layout.tsx !profile || profile.account_type ≠ 'brand' redirect /dashboard

campaigns/[id]/edit/page.tsx !campaign notFound() → 404
Server Action: createCampaign !profile || account_type ≠ 'brand' return { errors: { general: 'Unauthorized.' } }
Server Action: updateCampaign !profile || account_type ≠ 'brand' return { errors: { general: 'Unauthorized.' } }
Server Action: deleteCampaign !profile || account_type ≠ 'brand' return { error: 'Unauthorized.' }

Middleware Supabase

Plik: src/lib/supabase/middleware.ts

Wywoływany przy każdym żądaniu. Odświeża sesję Supabase (tokeny JWT w cookies) bez blokowania ruchu — guard logiki routingu znajduje się w layoutach, nie w middleware.

DAL — Data Access Layer

src/lib/dal.ts jest oznaczony jako server-only. Eksportuje funkcje opakowane w React.cache() — zapytania są deduplikowane w ramach jednego renderowania:

FunkcjaOpis
getUser()Pobiera bieżącego użytkownika z Supabase Auth
getProfile()Pobiera profil z tabeli profiles
getCampaigns()Lista kampanii marki (filtr: brand_id = user.id, sortowanie: created_at DESC)
getCampaign(id)Pojedyncza kampania (filtr: id + brand_id)

9. Server Actions

auth.ts — akcje autoryzacji

AkcjaWejścieSukcesBłąd
signUp accountType, email, password redirect /onboarding state.errors (Zod + Supabase)
signIn email, password redirect /dashboard lub /onboarding state.errors.general
signOut — redirect / brak (ignorowany)
completeOnboarding first_name/last_name lub brand_name + disciplines redirect /dashboard state.errors (Zod + Supabase)

campaigns.ts — akcje kampanii

AkcjaWejścieSukcesBłąd
createCampaign title, description, disciplines[] redirect /dashboard/campaigns state.errors
updateCampaign(id) title, description, disciplines[] redirect /dashboard/campaigns state.errors
deleteCampaign id (hidden field) redirect /dashboard/campaigns state.error (string)

Wzorzec useActionState

Wszystkie formularze klienckie używają hooka useActionState z React 19:

const [state, action, pending] = useActionState(serverAction, undefined)

// state → poprzedni zwrot z akcji (błędy, komunikaty)
// action → handler przekazywany do form action={action}
// pending → boolean, true gdy akcja w toku (blokuje submit button)

10. Opisy widoków

/ — Strona główna

Typ: React Server Component

Layout: (main)/layout.tsx — nagłówek publiczny

Zawartość: Pusta strona — placeholder dla przyszłej landing page

Nagłówek: Nawigacja „For Athletes" / „For Brands" + przyciski SIGN IN / JOIN (lub DASHBOARD gdy zalogowany)

/login — Logowanie

Typ: Client Component ('use client')

Elementy:

  • Input email (type=email, autocomplete)
  • Input password (type=password)
  • Przycisk „Sign In" (disabled podczas pending)
  • Link do rejestracji
  • Komunikaty błędów inline przy każdym polu

Stan: useActionState(signIn)

/register — Rejestracja

Typ: Client Component

Elementy:

  • Toggle buttons: Athlete / Brand — z wizualnym stanem active (aria-pressed)
  • Input email + password
  • Przycisk „Join" (disabled podczas pending)
  • Link do logowania

Stan: useState(accountType) + useActionState(signUp)

Ukryte pole: <input type="hidden" name="account-type" value={accountType} />

/onboarding — Uzupełnienie profilu

Typ: Page — RSC, Form — Client Component

Elementy (Athlete): First name, Last name, DisciplinePicker

Elementy (Brand): Brand name, DisciplinePicker

DisciplinePicker: Toggle buttons dla Crossfit / Triathlon / Motorsports. Wybrany stan w Set<Discipline>. Emituje ukryte inputy.

Stan: useActionState(completeOnboarding)

10. Opisy widoków (cd.)

/dashboard — Panel główny

Typ: RSC

Zawartość: Pusta strona — placeholder. Nagłówek zawiera linki: My Campaigns, My Profile (placeholder) + SIGN OUT

/dashboard/campaigns — Lista kampanii

Typ: RSC

Dane: getCampaigns() — pobrane po stronie serwera

Elementy:

  • Przycisk „New Campaign" (prawy górny róg)
  • Stan pusty: komunikat + link do tworzenia
  • Lista kart z: tytułem, opisem (2 linie), statusem jako badge, linkiem Preview

Kolejność: malejąca wg created_at

/dashboard/campaigns/new — Nowa kampania

Typ: Page — RSC, Form — Client Component

Elementy formularza:

  • Title: input text, max 200 znaków
  • Description: textarea 6 wierszy, max 5000 znaków
  • DisciplinePicker (min 1 wymagana)
  • Przycisk „Create Campaign" (pending: „Creating…")

Walidacja: Zod po stronie serwera — błędy inline przy polach

/dashboard/campaigns/:id — Szczegóły kampanii

Typ: RSC

Elementy:

  • Link powrotu „← Back to Campaigns"

  • Opis (whitespace-pre-wrap, pełny tekst)
  • Dyscypliny jako pill badges z labelami

DisciplinePicker: defaultValue={campaign.disciplines ?? []}
