Lista poprawek

#1
SignInSchema — walidacja pustego emaila
src/app/actions/auth.ts
Zmieniono z.email() na z.string().min(1).email() — pusty email zwracał "Enter a valid email address." zamiast wymaganego przez test "Email is required."
#2
signIn — komunikat błędu nieprawidłowych danych logowania
src/app/actions/auth.ts
"Invalid email or password." → "Invalid login credentials." — test E2E sprawdzał regexem /invalid login credentials/i, stary komunikat nie pasował.
#3
Main layout — przycisk Sign Out dla zalogowanych użytkowników
src/app/(main)/layout.tsx
Dodano showSignOut={!!user}. Użytkownik bez ukończonego onboardingu trafiał na /onboarding (redirect z /dashboard), gdzie nie było przycisku Sign Out — testy 4, 6, 7 nie mogły się wylogować.
#4
Kampanie — strict mode violation przy getByText('draft')
tests/e2e/campaigns.spec.ts
Dodano { exact: true }. getByText('draft') (case-insensitive substring) dopasowywał 3 elementy: tytuł "Draft Campaign", opis "...in draft state." i badge statusu — strict mode wymaga dokładnie jednego.
#5
Login page — renderowanie i mocki błędów pól formularza
src/app/(main)/(customer)/login/page.tsx & page.test.tsx
Zmieniono {state.errors.email} na {state.errors.email[0]} (typ to string[]). Sparowane z mockami: 'Error' → ['Error'] — bez tej zmiany 'string'[0] = 's' łamałoby testy.
#6
Register page — renderowanie i mocki błędów pól formularza
src/app/(main)/(customer)/register/page.tsx & page.test.tsx
Ta sama klasa problemu co #5: pola accountType, email, password (wszystkie string[]) renderowane bez [0]. Mocki zaktualizowane do tablic. Spójne teraz z onboarding-form.tsx i campaign-form.tsx.
